2. KEY FINDING (READ THIS FIRST)
--------------------------------------------------------------------------------
1-minute candle features -> 5-minute DOGE direction gives only:

    XGBoost   45.55% test acc   macro-F1 0.322
    LightGBM  45.63% test acc   macro-F1 0.323
    MLP       45.78% test acc   macro-F1 0.324
    majority-class baseline ~ 42.7%

Backtest loses ~100% at low confidence; at a 0.6+ confidence gate there are
almost no trades. Net of the 0.24%/trade cost, candle-only features are NOT
tradable. CONCLUSION: the predictive signal for small movements lives in
MICROSTRUCTURE (order book / trade flow), not candles. Build that first (7A).

6A. MICROSTRUCTURE COLLECTOR (WebSocket)  <-- HIGHEST PRIORITY, CPU-OK
--------------------------------------------------------------------------------
Build `src/microstructure.py`. Stream from Bybit V5 public WebSocket:

    wss://stream.bybit.com/v5/public/spot

Topics per symbol (DOGEUSDT / BTCUSDT / XAUTUSDT):
    orderbook.1.<SYMBOL>    level-1: best bid/ask + sizes
    orderbook.50.<SYMBOL>   depth (50 levels) if you want a real imbalance
    publicTrade.<SYMBOL>    each public trade (price, side, size, ts)

Aggregate to 1-minute bars and store to:
    data/microstructure/<SYMBOL>_1m_micro.csv

Columns to compute (per minute):
    spread            = ask - bid
    rel_spread        = spread / mid
    mid_price         = (bid + ask) / 2
    ob_imbalance      = (bid_vol - ask_vol) / (bid_vol + ask_vol)   # -1..+1
    buy_volume        = sum(buy-side trade size)
    sell_volume       = sum(sell-side trade size)
    trade_count
    large_trade_count = trades > k * rolling_median(size)
    vwap
    trade_imbalance   = (buy_vol - sell_vol) / (buy_vol + sell_vol)

Implementation notes:
  - Use `websocket-client` or `websockets` lib (pip install websockets).
  - Subscribe to all 3 symbols in ONE connection (comma-separated topics).
  - Keep the loop resilient (auto-reconnect, ping/pong).
  - Save a partial CSV every minute so a crash never loses more than a minute.
  - Run it for several days BEFORE retraining; you need a real micro history.

Then extend `src/features.py` to merge micro columns into the feature matrix
(synchronized on the same UTC minute index) and retrain the baselines.

6D. MULTI-HEAD TARGETS  (Phase 10)
--------------------------------------------------------------------------------
Output heads (instead of only 3-class direction):
    future_ret_1..future_ret_5   (regression, MSE/Huber)
    direction P(UP/DOWN/NOMOVE)  (cross-entropy)
    future_vol                   (regression)
    future_max_up / future_max_down (regression)
Loss = weighted sum. The target columns already exist in data/features/targets.csv;
the current models only use `label`. Wire the extra heads into the model + trainer.

--------------------------------------------------------------------------------
6E. MULTI-TIMEFRAME TRANSFORMER  (Phase 8 + 13)
--------------------------------------------------------------------------------
Three parallel branches:
    1m  x 30   (fast)
    5m  x 36   (medium)
    15m x 32   (slow)
Each branch: positional encoding -> TransformerEncoder (or GRU) -> pooling.
Then cross-asset attention (DOGE / BTC / XAUT), a temporal transformer, and the
multi-head output from 6D, ending in a confidence gate.

Suggested starting hyperparams (search space for evolution):
    d_model    : 256 / 512 / 768 / 1024
    layers     : 4 / 6 / 8 / 10 / 12
    heads      : 4 / 8 / 12 / 16
    dropout    : 0.1 / 0.15 / 0.2 / 0.3
    lr         : 1e-4 / 5e-5 / 1e-5
    weight_decay: 0.0 / 0.01 / 0.02
    seq_len    : 30 / 60 / 90
    feature_subset: random subsets of the feature columns
    loss_weights: random (direction vs returns vs vol)


--------------------------------------------------------------------------------
6F. EVOLUTION ENGINE  (Phases 13-18)
--------------------------------------------------------------------------------
Build `src/evolution_gpu.py` (or extend evolution.py to the transformer).

Do NOT start with 100 x 200M models. Start small and scale the winners:

    Generation 0 : 100 models, 20-80M params each
    -> train on TRAIN, score on VALIDATION-A
    -> keep TOP 10
    Generation 1..N : mutate + crossover survivors -> 100 children
    -> repeat 20-50 generations
    -> scale the best architectures to 100-250M params
    -> final ensemble

Randomize per individual (genes):
    d_model, layers, heads, dropout, lr, weight_decay, seq_len,
    feature_subset, loss_weights, optimizer

Scoring (tune weights; lean on net-of-fee performance):
    score = 0.20 * direction_acc
          + 0.15 * f1
          + 0.15 * precision
          + 0.15 * return_mae (neg)
          + 0.20 * trading_sim_pnl
          + 0.15 * calibration

DIVERSITY (critical): keep top-K, but drop near-duplicates — measure pairwise
prediction correlation on a held-out slice; if corr > 0.9, keep only one.

Mutation: perturb 1-3 genes (e.g. layers 8->10, lr *0.75, dropout +/-0.05).
Crossover: swap genes between two parents (d_model from A, layers from B).

Log every individual to results/generation_NNN.csv:
    model_id, generation, genes..., val_loss, acc, precision, recall, f1,
    mae, simulated_return, profit_factor, drawdown, diversity_flag

Never let the evolution loop touch FINAL TEST.

--------------------------------------------------------------------------------
6G. ENSEMBLE + CONFIDENCE GATE  (Phases 21-22)
--------------------------------------------------------------------------------
After evolution, pick 5-10 strong AND diverse models. Final prediction =
weighted average of their probabilities (weights from val performance).
Apply a confidence gate: only emit LONG/SHORT when P(class) >= threshold
(start 0.7; tune on validation). Otherwise NO TRADE.

--------------------------------------------------------------------------------
9. PITFALLS / RULES
--------------------------------------------------------------------------------
  - The FINAL TEST set must stay untouched by evolution and hyperparameter search.
  - 95% accuracy is a red flag -> check leakage (lookahead, feature/target overlap).
  - Do NOT interpolate missing candles blindly (market closed vs collection failed).
  - Score models on NET return after fees/slippage, not raw accuracy.
  - Prefer diverse top models over correlated duplicates.
  - Start small (20-80M), scale winners (100-250M) only after signal is proven.
  - The first MLP baseline took 23 min on CPU; on GPU this becomes seconds/minutes,
    which is exactly why the transformer + evolution phases move to a GPU PC.
